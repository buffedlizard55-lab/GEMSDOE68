Correctness bug that invalidated the first experiment run

The row-halo padding in src/gems68/blocks.py was mis-aligned. top = max(0, r0 - pad - a) returns 0 at the raster's top edge, so any prediction strip that began at row 0 produced a short block; the subsequent out[:, pad:pad + nrows] then cropped the wrong rows. Every prediction strip was shifted by PAD_STAGE2 = 18 rows. The correct form is max(0, a - (r0 - pad)), which is clamped only by the array boundary and otherwise yields exactly pad.

Consequence: every stage-1 and stage-2 holdout DTI computed before the fix was wrong, and the first experiment run was killed and restarted. The bug is now pinned by tests/test_blocks68.py::test_read_rows_halo_and_columns and test_halo_cropping, which assert that the block height is always nrows + 2 * pad.

Measurement limitations, stated plainly

  • No organiser score. The competition's scoring truth is login-walled. Every number on this site is a local HOLDOUT-DTI measured against withheld catalogue segments. None of them is an official score.
  • The holdout is the catalogue. Withholding whole segments of the mapped fault catalogue measures how well the model recovers faults that somebody has already mapped, not how well it discovers faults nobody has mapped. That is a real gap and it is the main reason the leakage canary is reported alongside the DTI.
  • The 3-px overlap rule is degenerate here. The footprint is small and densely dotted by earlier sessions, so "more than 70 % of this raster's dots lie within 3 px of one registry raster's dots" is close to trivially true. The measurement is reported as measured, with that caveat, rather than silently passed.
  • Budget overrun. The protocol allows three experiments and two hours. The first experiment run was lost to the halo bug and had to be restarted from scratch; the restarted run is what produced every number here. The wall-clock overrun is recorded in the run card rather than hidden.
  • Test coverage is partial. 18 tests pin the shared tools, the block builder and the halo cropping. The auto-context stacking itself is not unit-tested against an independent implementation; it is only validated by the holdout gate.
