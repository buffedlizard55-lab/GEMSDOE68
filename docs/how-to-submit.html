How to make a submission (step by step)

  1. Download the primary file: ⬇ gems68-autoctx-s3-hidedraw-38000dots-20261012T022132Z-4c18def6-zeros.tif (or the ZIP containing only that TIFF). Verify its SHA-256 matches 3495c83f82b723d84dea1e99adbe5fbd94e46133cf5f3deb9fe310b42135bc59.
  2. Open the competition's submission page (login required) and click New submission.
  3. File to submit: choose the downloaded .tif (or .zip). The form accepts a single-band GeoTIFF matching the sample's CRS (EPSG:32611), shape (3730×3292) and geotransform.
  4. Note (optional, ≤140 characters): paste GEMSDOE68 auto-context s3 hide-draw; 38000 dots >2px off catalogue; HOLDOUT-DTI 0.1189 vs s1 0.0816; UNSCORED
  5. Submit. Copy the score from the receipt into registry/score_ledger.csv tagged ORGANIZER-CONFIRMED with the exact file name and SHA-256.

About the earlier "Predicted values must be in range [0, 1]" error

The primary file here is all-finite: 0.0 outside the footprint, values exactly 0.0 or 1.0 inside, no NaN, no nodata tag, no sentinel. The family's champion (0.2778) was uploaded in this "zeros" form. A NaN-outside variant is also published (the public spec permits NaN outside the footprint and several NaN-variants scored in the ledger), but if the portal rejects it for range, use the zeros file. The local validator re-reads the bytes on disk and checks: single band, float32, 3730×3292, EPSG:32611, pinned transform, no NaN/inf anywhere, min ≥ 0, max ≤ 1, zero positive pixels outside the footprint, zero positive pixels on the mapped catalogue.

Rules you should know

  • Weekly submission cap is shown on the submission page; promotion to a slot is a separate selector decision (rules PDF 96647).
  • Metric: distance-weighted Tversky index, α = 0.2 (FP), β = 0.8 (FN), 300 m triangular kernel (problem description).
  • Known/mapped faults are excluded from scoring; the truth is new faults mapped by the expert panel.
