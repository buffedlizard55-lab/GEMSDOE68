Why -zeros.tif Resolves "Predicted values must be in range [0, 1]"

DrivenData's submission form rejected an earlier NaN-masked file with "Predicted values must be in range [0, 1]" because IEEE-754 NaN fails unmasked (arr >= 0.0) & (arr <= 1.0) range checks. Our primary file (gems68-autoctx-s3-strands-35000dots-20261020T210000Z-849a0f04-zeros.tif) is 100% finite across all 12,279,160 grid cells (0.0 outside the footprint, 0.0 on background footprint pixels, and calibrated probabilities in [0.500, 1.000] on the 35,000 emitted fault dots). A secondary NaN-outside twin (gems68-autoctx-s3-strands-35000dots-20261020T210000Z-849a0f04-nan.tif, SHA-256 3f9553609ad7260f9e9a5520bde56ed4a728a9fa484e78fd59fe764101f8185d) is also provided for byte-for-byte nodata parity with sample_submission.tif.
