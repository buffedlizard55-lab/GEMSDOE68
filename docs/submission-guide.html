2. Upload

  1. Go to the competition submissions page and press New submission.
  2. File to submit: choose the downloaded .tif. A .zip containing exactly one GeoTIFF is also accepted; the repository ships …-nan.zip next to the .tif.
  3. Note (optional): paste
    GEMSDOE68 auto-context stacked refinement (Tu CVPR 2008); stage2, r=3px, 20000 dots; holdout-gated
  4. Press Create submission.

3. Verify locally before uploading (optional)

# from the repository root, with the competition data placed under data/
PYTHONPATH=src python -m gems.validate_submission \
    docs/downloads/<file>.tif \
    --reference data/bridge/sample_submission.tif \
    --features  data/bridge/training_features.tif

# duplicate / lane check against every prior raster in the registry
python scripts/lane_check.py --stage emitted \
    docs/downloads/<file>.tif registry/rasters/*.tif \
    --json evidence/ac68_lane_check.json

Both commands are read-only. validate_submission exits 0 only when every required check passes; SKIPPED is never treated as a pass.

4. Reproduce the file from scratch

# 1. place the competition data (see README "Data placement")
# 2. build the cached 45-channel stack (takes ~1 minute)
PYTHONPATH=src python -c "from gems68 import features as F; F.load_channels()"
# 3. holdout experiment + emission-parameter sweep (~25 min)
PYTHONPATH=src python scripts/run_autocontext.py --seeds 20 \
    --dot-budget 32000 --out evidence/ac68_seed20.json
# 4. emit the submission with the parameters tuned in step 3
PYTHONPATH=src python scripts/emit_submission.py \
    --params evidence/ac68_emission_params.json \
    --name GEMSDOE68-AC-stack3 --out docs/downloads
# 5. lane check, then rebuild the site from the evidence
python scripts/lane_check.py --stage emitted docs/downloads/*-nan.tif \
    registry/rasters/*.tif --json evidence/ac68_lane_check.json
PYTHONPATH=src python scripts/build_site.py
